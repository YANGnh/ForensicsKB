# 2026 广西职业技能大赛 初赛

## 挑战 1：autumn1.png

### autumn1.png

## 题目概述

题目提供了一个损坏的 PNG 图片 `autumn1.png`，要求分析图片结构、修复损坏并提取 flag。核心漏洞在于 IHDR 块中的宽度与高度被篡改，但 CRC 校验值未被更新，通过 CRC 反推与 IDAT 数据量验证即可还原真实尺寸。flag 以明文形式直接绘制在修复后的图片中。

## 文件信息

- **文件名**：`autumn1.png`
- **大小**：2,811,080 bytes
- **格式**：PNG (Portable Network Graphics)
- **损坏类型**：IHDR 块宽高字段被篡改，CRC 未随之更新

## 解题过程

### 步骤 1：分析 IHDR 块

PNG 文件的第一个数据块为 IHDR，包含图像的基本元信息。解析原始文件中的 IHDR 块：

```
偏移      内容
0x00-0x03  49 48 44 52   ("IHDR" 标识)
0x04-0x07  00 00 04 B0   宽度 = 1200 (小端)
0x08-0x0B  00 00 02 F3   高度 = 755  (小端)
0x0C       08             位深度 = 8
0x0D       02             颜色类型 = 2 (RGB)
0x0E-0x10  00 00 00      压缩/滤波/隔行 = 0
0x11-0x14  B0 38 C0 84   存储的 CRC32
```

读取到的尺寸为 **1200x755**，CRC 校验值为 `0xB038C084`。

```python
import struct

with open("autumn1.png", "rb") as f:
    data = f.read()

ihdr_offset = data.index(b"IHDR")
width  = struct.unpack(">I", data[ihdr_offset+4 : ihdr_offset+8])[0]
height = struct.unpack(">I", data[ihdr_offset+8 : ihdr_offset+12])[0]
stored_crc = struct.unpack(">I", data[ihdr_offset+17 : ihdr_offset+21])[0]

print(f"当前尺寸: {width}x{height}")
print(f"存储CRC:  0x{stored_crc:08X}")
### 输出: 当前尺寸: 1200x755
### 输出: 存储CRC:  0xB038C084
```

### 步骤 2：CRC 校验 —— 定位真实尺寸

CRC32 校验值覆盖 `"IHDR"` 标识后的 17 字节数据。分别计算当前尺寸与候选尺寸的 CRC：

```python
import zlib

### IHDR 数据模板 (位深度=8, 颜色类型=2, RGB)
ihdr_tail = bytes([0x08, 0x02, 0x00, 0x00, 0x00])

### 当前尺寸 (1200x755)
crc_1200x755 = zlib.crc32(b"IHDR" + struct.pack(">II", 1200, 755) + ihdr_tail)
print(f"1200x755 CRC: 0x{crc_1200x755 & 0xFFFFFFFF:08X}")
### 输出: 1200x755 CRC: 0x8E5F6960

### 候选尺寸 (1575x955)
crc_1575x955 = zlib.crc32(b"IHDR" + struct.pack(">II", 1575, 955) + ihdr_tail)
print(f"1575x955 CRC: 0x{crc_1575x955 & 0xFFFFFFFF:08X}")
### 输出: 1575x955 CRC: 0xB038C084  ← 与存储CRC一致！
```

1200x755 的 CRC 为 `0x8E5F6960`，与存储值 `0xB038C084` 不匹配。而 **1575x955** 的 CRC 恰好等于存储值，说明原始尺寸被从 `1575x955` 篡改为 `1200x755`，但 CRC 未被更新。

### 步骤 3：IDAT 数据量二次验证

为排除 CRC 碰撞的可能，进一步验证解压后的 IDAT 数据总量。对于 RGB (3 通道) PNG，每行数据量为 `1 + 宽度 * 3`（1 字节行滤波标识 + 3 字节/像素），总数据量为 `高度 * (1 + 宽度 * 3)`。

```python
import zlib

### 收集所有 IDAT 块并解压
pos = 0
compressed = b""
while True:
    pos = data.find(b"IDAT", pos)
    if pos == -1:
        break
    chunk_len = struct.unpack(">I", data[pos-4:pos])[0]
    compressed += data[pos+4 : pos+4+chunk_len]
    pos += 4

decompressed = zlib.decompress(compressed)
print(f"解压后大小: {len(decompressed)} bytes")

### 理论计算
expected_1200x755 = 755 * (1 + 1200 * 3)   # = 2,718,755
expected_1575x955 = 955 * (1 + 1575 * 3)   # = 4,513,330

print(f"1200x755 预期: {expected_1200x755} 匹配: {len(decompressed) == expected_1200x755}")
print(f"1575x955 预期: {expected_1575x955} 匹配: {len(decompressed) == expected_1575x955}")
### 输出: 1200x755 预期: 2718755 匹配: False
### 输出: 1575x955 预期: 4513330 匹配: True
```

解压后的 IDAT 数据恰好为 4,513,330 字节，与 `955 * (1 + 1575 * 3)` 完全吻合，双重确认真实尺寸为 **1575x955**。

### 步骤 4：修复图片

将 IHDR 中的宽高字段覆盖为正确值，CRC 保持不变（已正确）。

```python
### 宽: 1200 (0x04B0) → 1575 (0x0627)
### 高: 755  (0x02F3) → 955  (0x03BB)

patched = bytearray(data)
ihdr_offset = patched.find(b"IHDR")
struct.pack_into(">I", patched, ihdr_offset + 4, 1575)   # 覆写宽度
struct.pack_into(">I", patched, ihdr_offset + 8, 955)    # 覆写高度

with open("fixed_correct.png", "wb") as f:
    f.write(patched)

print("修复完成 → fixed_correct.png (1575x955)")
```

修复后的图片文件位于：`/mnt/c/Users/mlzxg/Documents/CouldDelete1/fixed_correct.png`

### 步骤 5：提取 Flag

修复后的图片可以直接用任何图片查看器打开，flag 以明文文本形式直接绘制在图像中。**未发现任何通道存在 LSB 隐写**。

可通过 OCR 或直接肉眼识别，flag 清晰可见：

```
flag{3ddf0d1b188930c661b7ad575eaea834}
```

## Flag

```
flag{3ddf0d1b188930c661b7ad575eaea834}
```

## 关键工具

- **Python 3** (`struct`, `zlib`) — PNG 结构解析、CRC 计算、IDAT 解压验证、字节覆写
- 任意图片查看器 — 查看修复后图片，直接读取 flag

## 总结

本题考察 PNG 文件格式的基本理解与数据完整性校验能力：

1. **IHDR 块结构**：前 16 字节（4 字节标识 + 4 字节宽 + 4 字节高 + 5 字节元数据）后跟 4 字节 CRC32
2. **CRC 反推**：存储的 CRC 校验值与当前声明的尺寸不匹配，说明尺寸被篡改但 CRC 未更新；通过暴力枚举或合理推断候选尺寸，找到 CRC 匹配的真实尺寸
3. **IDAT 大小验证**：解压后的像素数据量必须与 `高度 * (1 + 宽度 * 通道数)` 严格一致，用于排除 CRC 碰撞并交叉确认正确尺寸
4. **直接修复**：覆盖 IHDR 中错误的宽高字段即可恢复图片，CRC 无需修改

## 挑战 2：Base64.exe

### Base64.exe

## 摘要

题目给出了一个 Windows 可执行文件 `Base64.exe`，程序内部使用了一套自定义的 Base64 编码表，并将 flag 编码后硬编码在程序中。通过提取自定义编码表、将编码字符串映射回标准 Base64 并解码，即可获得 flag。

## 解题过程

### 第一步：提取自定义 Base64 编码表

使用静态分析工具（如 IDA、Ghidra 或 `strings`）对 `Base64.exe` 进行逆向分析，在程序的只读数据段中发现了一个长度为 64 的字符串，即自定义的 Base64 编码表：

```
AaBbCcDdEeFfGgHhIiJjKkLlMmNnOoPpQqRrSsTtUuVvWwXxYyZz0987654321/+
```

该编码表与标准 Base64 编码表的对应关系为：**自定义表中索引 `i` 处的字符，对应于标准 Base64 编码表中索引 `i` 处的字符**。即：

| 索引范围 | 自定义编码表 | 标准编码表 |
| -------- | ------------ | ---------- |
| 0-25     | AaBb...YyZz  | A-Z        |
| 26-51    | aAbB...yYzZ  | a-z        |
| 52-61    | 0987654321   | 0-9        |
| 62       | /            | +          |
| 63       | +            | /          |

### 第二步：提取硬编码的加密字符串

在同一二进制文件的 `.rdata` 段中，找到了一段被自定义 Base64 编码过的字符串：

```
mTyqm7wwMlspMTkpNlipNlgpnT10l7gxl8qqOTi1
```

### 第三步：映射回标准 Base64 并解码

将加密字符串中的每个字符，通过自定义编码表到标准编码表的索引映射关系进行替换，得到标准 Base64 编码：

```
ZmxhZ3ttYXlfYmVfaXRfaXNfbm90X3NvX2hhcmR9
```

对上述标准 Base64 字符串进行解码，得到 flag：

```python
#!/usr/bin/env python3
import base64

### 自定义 Base64 编码表
CUSTOM = "AaBbCcDdEeFfGgHhIiJjKkLlMmNnOoPpQqRrSsTtUuVvWwXxYyZz0987654321/+"
### 标准 Base64 编码表
STD    = "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/"

trans = str.maketrans(CUSTOM, STD)

encoded = "mTyqm7wwMlspMTkpNlipNlgpnT10l7gxl8qqOTi1"
std_b64 = encoded.translate(trans)

flag = base64.b64decode(std_b64).decode()
print(flag)
```

运行输出：

```
flag{may_be_it_is_not_so_hard}
```

## 挑战 3：b.pcapng 流量分析 - 还原黑客窃取文件

### b.pcapng 流量分析 - 还原黑客窃取文件

## 题目描述

> 请分析 b.pcapng 流量包，还原黑客窃取的文件内容。

## 解题思路

本题是一道网络流量取证题目，核心思路是通过分析 FTP 流量，从数据流中提取 RAR 压缩包，再破解密码获取最终 flag。

## 解题步骤

### 步骤一：分析流量包

使用 Wireshark 打开 `b.pcapng`（34,560 字节），发现流量主要为 FTP 协议通信，源 IP 为 `172.16.66.188`，目标 IP 为 `172.16.66.10`。

通过追踪 TCP 流（TCP stream 4，frame 55），发现 FTP-DATA 通道传输了一个 RAR 压缩包。将该流的数据导出为 `extracted.rar`（164 字节）。

### 步骤二：导出并识别 RAR 文件

使用 `xxd` 或十六进制编辑器查看文件头部，确认魔数为：

```
52 61 72 21 1a 07 00
```

对应 ASCII 字符串 `Rar!\x1a\x07\x00`，说明这是一个 RAR3 格式的压缩包。进一步分析 RAR 头部结构，发现 `HEAD_FLAGS` 中 `0x0080` 位被置位，表明该压缩包设置了密码保护。

```bash
### 从 TCP 流提取 RAR 文件（Wireshark 操作）
tshark -r b.pcapng -Y "tcp.stream eq 4" -T fields -e data | xxd -r -p > extracted.rar

### 验证文件头
xxd extracted.rar | head -n 1
### 输出: 00000000: 5261 7221 1a07 00ce 9900 0000 0000 0000  Rar!............
```

### 步骤三：破解 RAR 密码

由于 RAR 文件设置了密码，使用 John the Ripper 结合 rockyou 字典进行破解。

```bash
### 使用 rar2john 提取哈希
rar2john extracted.rar > rar.hash

### 使用 john 配合 rockyou 字典破解
john --wordlist=/usr/share/wordlists/rockyou.txt rar.hash
```

破解结果：密码为 `5790`。

使用密码解压：

```bash
unrar x -p5790 extracted.rar
```

解压得到 `flag.txt`，内容即为最终 flag。

## Flag

```
flag{6fe99a5d03fb01f833ec3caa80358fa3}
```

## 工具与环境

| 工具 | 用途 |
|------|------|
| Wireshark / tshark | 流量分析与数据导出 |
| xxd | 十六进制查看 |
| John the Ripper + rar2john | RAR 密码破解 |
| rockyou 字典 | 弱密码爆破词表 |

## 知识点

1. FTP 协议使用两条独立的 TCP 连接：控制连接（端口 21）和数据连接（端口 20），文件通过数据连接传输。
2. RAR 文件头部结构：魔数 `Rar!\x1a\x07\x00` 标识 RAR 格式版本（RAR3/RAR4 为 `\x07\x00`，RAR5 为 `\x1a\x07\x01\x00`）。
3. RAR 头部标志位 `0x0080`（PASSWORD）指示压缩包已加密。
4. 对于弱密码保护的压缩包，字典攻击是高效且常用的破解手段。

## 挑战 4：challengep.elf

### challengep.elf

## 题目概述

一个经过 UPX 4.24 加壳且修改了魔数的 ELF 64-bit 静态链接可执行文件。需要从不同层次提取三个 flag：Flag1 藏于加壳后明文字符串，Flag2 藏于运行时解压后的内存映射只读段，Flag3 需要通过逆向校验算法推导输入。

## 文件信息

- **文件名**：`challengep.elf`
- **大小**：9055 bytes
- **类型**：ELF 64-bit LSB PIE executable, x86-64, statically linked, no section header
- **加壳**：UPX 4.24，魔数字节被修改（标准 UPX! 为 `55 50 58 21`，此文件偏移 0xea 处为 `6a 7a 55 50 58 21` 即 `jzUPX!`），导致标准 `upx -d` 无法解压

## 解题过程

### Flag1 — 明文字符串提取

UPX 加壳并未对未压缩的元数据部分做有效混淆，flag1 直接以明文形式存在于加壳后的二进制文件中。

```bash
strings challengep.elf | grep flag1
### 输出：flag1{d18b8fe662c29a351c037bbc97af08af}
```

**Flag1: `flag1{d18b8fe662c29a351c037bbc97af08af}`**

---

### Flag2 — 运行时内存解压提取

由于魔数被修改，标准 UPX 工具无法直接解压。程序运行时会自解压并将代码和数据映射到三个匿名内存区域：

| 权限   | 用途           |
|--------|----------------|
| `rwx`  | 解压器代码段   |
| `r-xp` | 解压后代码段   |
| `r--p` | 解压后只读数据 |

Flag2 位于解压后的 `.rodata` 只读数据段（`r--p` 匿名映射区域）。提取方法：

1. 运行二进制并挂起/观察：
```bash
./challengep.elf &
PID=$!
sleep 0.5
```

2. 通过 `/proc/<pid>/maps` 找到 `r--p` 匿名映射区域：
```bash
cat /proc/$PID/maps | grep 'r--p'
### 示例输出：
### 7f1234560000-7f1234561000 r--p 00000000 00:00 0
```

3. 从 `/proc/<pid>/mem` 中 dump 该区域并搜索 flag：
```bash
### 解析起止地址
START=$(cat /proc/$PID/maps | grep 'r--p' | head -1 | cut -d'-' -f1)
END=$(cat /proc/$PID/maps | grep 'r--p' | head -1 | cut -d'-' -f2 | cut -d' ' -f1)

### 使用 dd 从进程内存中提取
dd if=/proc/$PID/mem bs=1 skip=$((16#$START)) count=$((16#$END - 16#$START)) 2>/dev/null | strings | grep flag2
### 输出：flag2{3edf2e185efd6a6585b9e474a3120eaf}
```

**Flag2: `flag2{3edf2e185efd6a6585b9e474a3120eaf}`**

---

### Flag3 — 逆向校验算法

程序解压后内部实现了一个自定义校验算法，用户输入 39 字节的 flag 后程序会进行验证并输出 "Correct! Flag accepted."。

#### 算法分析

通过逆向解压后代码，还原出以下核心要素：

**1. 密钥 (10 bytes)**
```
UPX_2026!!
```

**2. LUT (256 字节双射置换表)**

位于数据偏移 0x60 处，是一个 256 字节的一一映射置换表（bijective substitution）。

**3. 预期密文 (39 bytes)**
```
32 f8 e9 71 88 a1 b0 d2 eb db 13 60 9e 02 2b bb b0 e2 ee 7e
32 8f 96 9e 5d bb 2f e2 8e eb 61 35 9b 02 36 bb 36 bb f3
```

**4. 加密/校验逻辑**
```
output[i] = LUT[input[i] XOR key[i % 10]]
```
程序将用户输入的 flag 每个字节与密钥循环异或后，以结果作为索引查 LUT 表，得到的值若与内置密文一致则验证通过。

#### 求解脚本

由于 LUT 是双射，可以构建逆 LUT 直接还原 flag：

```python
#!/usr/bin/env python3

### 密钥
key = b"UPX_2026!!"

### 预期密文（从解压后镜像提取）
ciphertext = bytes([
    0x32, 0xf8, 0xe9, 0x71, 0x88, 0xa1, 0xb0, 0xd2, 0xeb, 0xdb,
    0x13, 0x60, 0x9e, 0x02, 0x2b, 0xbb, 0xb0, 0xe2, 0xee, 0x7e,
    0x32, 0x8f, 0x96, 0x9e, 0x5d, 0xbb, 0x2f, 0xe2, 0x8e, 0xeb,
    0x61, 0x35, 0x9b, 0x02, 0x36, 0xbb, 0x36, 0xbb, 0xf3
])

### LUT（从解压后数据偏移 0x60 处提取的 256 字节）
### 此处省略完整 256 字节 LUT，实际解题时从内存 dump 中提取

### 构建逆 LUT
inv_lut = [0] * 256
for i in range(256):
    inv_lut[lut[i]] = i

### 解密
flag = []
for i in range(len(ciphertext)):
    x = inv_lut[ciphertext[i]]
    flag.append(x ^ key[i % len(key)])

print(''.join(chr(b) for b in flag))
### 输出：flag3{4cc2edcbe049b9f02dd0f90c0efb9096}
```

**Flag3: `flag3{4cc2edcbe049b9f02dd0f90c0efb9096}`**

## 挑战 5：DataMart 内鬼欺诈分析

### DataMart 内鬼欺诈分析

## Summary

通过对 DataMart 电商平台三张核心数据表（orders、users、products）的统计分析，定位了一起内鬼利用私有 IP 地址、gift_card 支付方式在 2024-03-15 批量刷单的欺诈案件，最终通过 $0.01 测试订单锁定攻击者。

## Solution

### Step 1: 数据规模与基准线统计

加载三张 CSV 表，统计基本指标建立分析基准线。

```python
import pandas as pd
import numpy as np

orders = pd.read_csv('orders.csv')
users = pd.read_csv('users.csv')
products = pd.read_csv('products.csv')

### Q1: 订单总记录数
print(f"Q1: {orders.shape[0]}")                    # 5521
```

## 挑战 8：traffic_master

### traffic_master

## Summary

给定一个 Rust 编译的 ELF 客户端二进制 `cli` 和一段 `traffic.pcap` 网络流量。客户端使用硬编码的 X25519 私钥与服务端进行 ECDH 密钥交换，随后通过 HKDF 派生 RC4 密钥加密通信。提取硬编码私钥、还原密钥交换过程即可解密流量获得 flag。

## Solution

### Step 1: 提取客户端硬编码的 X25519 私钥

运行二进制发现每次发送的 32 字节公钥完全相同，说明私钥是硬编码的。在二进制中扫描：以 8 字节为步长取 32 字节作为候选私钥，计算 X25519 公钥并与 pcap 中的客户端公钥比对，命中即得私钥。

### Step 2: 提取服务端公钥并计算共享密钥

pcap 中前两个 TCP payload 分别为客户端公钥（32B）和服务端公钥（32B）。使用 X25519 ECDH 计算共享密钥。

### Step 3: HKDF 派生 RC4 密钥并解密流量

逆向 `cli` 确认密钥派生使用 HKDF-SHA256，salt 为 `auth_protocol_salt`，info 为 `auth_protocol_key`。后续流量格式为 2 字节大端长度 + RC4 密文，解密即得 flag。

```python
from cryptography.hazmat.primitives.asymmetric import x25519
from cryptography.hazmat.primitives import hashes
from cryptography.hazmat.primitives.kdf.hkdf import HKDF
import struct, subprocess

class RC4:
    def __init__(self, key):
        self.S = list(range(256))
        j = 0
        for i in range(256):
            j = (j + self.S[i] + key[i % len(key)]) % 256
            self.S[i], self.S[j] = self.S[j], self.S[i]
        self.i = self.j = 0

    def crypt(self, data):
        result = bytearray()
        for byte in data:
            self.i = (self.i + 1) % 256
            self.j = (self.j + self.S[self.i]) % 256
            self.S[self.i], self.S[self.j] = self.S[self.j], self.S[self.i]
            k = self.S[(self.S[self.i] + self.S[self.j]) % 256]
            result.append(byte ^ k)
        return bytes(result)

### Step 1: 从二进制提取客户端硬编码私钥
import nacl.bindings
with open('cli', 'rb') as f:
    binary = f.read()
target_pub = bytes.fromhex('568d979fbf6fbbfde50014829a3e20436a272de4bdc324e526301aaebb0c9673')
for off in range(0, len(binary) - 32, 8):
    candidate = binary[off:off+32]
    if len(set(candidate)) <= 2:
        continue
    try:
        if nacl.bindings.crypto_scalarmult_base(candidate) == target_pub:
            client_priv = candidate
            print(f"[+] 私钥 @ 0x{off:x}: {client_priv.hex()}")
            break
    except:
        pass

### Step 2: 从 pcap 提取服务端公钥 → X25519 ECDH
result = subprocess.run(['tshark', '-r', 'traffic.pcap', '-Y', 'tcp.len > 0',
    '-T', 'fields', '-e', 'tcp.payload'], capture_output=True, text=True)
payloads = [bytes.fromhex(l) for l in result.stdout.strip().split('\n') if l]
server_pub = payloads[1]

pri_key = x25519.X25519PrivateKey.from_private_bytes(client_priv)
pub_key = x25519.X25519PublicKey.from_public_bytes(server_pub)
shared = pri_key.exchange(pub_key)

### Step 3: HKDF → RC4 → 解密
hkdf = HKDF(algorithm=hashes.SHA256(), length=32,
            salt=b"auth_protocol_salt", info=b"auth_protocol_key")
rc4 = RC4(hkdf.derive(shared))

buf, remain = b'', 0
for p in payloads[2:]:
    buf += p
    while len(buf) >= 2:
        if remain == 0:
            remain = struct.unpack('>H', buf[:2])[0]
            buf = buf[2:]
        if remain == 0 or len(buf) == 0:
            break
        take = min(remain, len(buf))
        print(rc4.crypt(buf[:take]).decode(), end='')
        buf, remain = buf[take:], remain - take
print()
```

```python
#!/usr/bin/env python3

### Encrypted data from the binary
encrypted = [

    0x30, 0x36, 0x45, 0x00, 0x1d, 0x1a, 0x45, 0x1e,

    for i in range(len(encrypted)):
        result.append(encrypted[i] ^ xor_key[i % 4])

    return bytes(result).decode('ascii')
```

### 黑客流量 (Hacker Traffic)

## Summary

## Solution

### Step 1: 解密冰蝎 Behinder 流量

从 PCAP 中提取 shell.php 的 POST 请求体。冰蝎默认密码 `rebeyond`，密钥为 MD5 前 16 位 `e45e329feb5d925b`。

加密方式：Base64 解码 → AES-128-CBC 解密（**IV 为 16 个零字节**，不是 key 本身）。

```python
import hashlib, base64, json, subprocess
from Crypto.Cipher import AES

password = "rebeyond"
key = hashlib.md5(password.encode()).hexdigest()[:16].encode()

def decrypt_behinder(data: bytes) -> bytes:
    decoded = base64.b64decode(data)
    cipher = AES.new(key, AES.MODE_CBC, iv=b"\x00" * 16)
    plain = cipher.decrypt(decoded)
    pad_len = plain[-1]
    if 0 < pad_len <= 16:
        plain = plain[:-pad_len]
    return plain

### Frame 2003 是 data.zip 下载响应
resp_raw = subprocess.run(
    ["tshark", "-r", "f.pcap", "-Y", "frame.number == 2003",
     "-T", "fields", "-e", "http.file_data"],
    capture_output=True, text=True
).stdout.strip()

resp_dec = decrypt_behinder(bytes.fromhex(resp_raw))
msg_b64 = json.loads(resp_dec)["msg"]
zip_data = base64.b64decode(base64.b64decode(msg_b64))  # 双 base64
```

data.zip 内含 `publickey1.pem`（n1）、`publickey2.pem`（n2，共用 e）和 `hint.txt`。

Hint 指出 `flag = md5(str(p) + str(q))`，只需分解 n1。factordb 直接命中：

### Step 3: 拼接 Flag

"大前小后"——较大的素数在前：

## 挑战 15：File Upload + Backdoor Analysis

### File Upload + Backdoor Analysis

## Summary

A network forensics challenge. A PHP webshell was uploaded via HTTP, then encrypted Python backdoor traffic on ports 8899/9999 was decrypted to recover the flag.

## Solution

### Step 1: Identify backdoor traffic

The pcap contains HTTP webshell uploads to `/ctf/upload.php` and TCP sessions on ports **8899** and **9999** with encrypted payloads. Decrypted `dir` output reveals `s3creT.txt` (16 bytes) and `server.py` on the server.

### Step 2: Reverse encryption protocol

The key `R@ns0mwar3_V1ru5` is read from `s3creT.txt`, with MD5 `ef578a404d5516ce43ea5da4e00a1601`.

Protocol: each message is encrypted as one unit, then TCP may fragment it:

1. JSON → **ARC4**(MD5 of key)
2. → **Base64**
3. → **XOR** each character with 4-byte Unix timestamp hex, truncated to the **frame's minute**
4. → UTF-8 bytes → TCP

Server responses split across TCP segments must be concatenated before decryption.

### Step 3: Decrypt and extract flag

```python
import hashlib, base64, subprocess, re
from collections import defaultdict
from Crypto.Cipher import ARC4
from datetime import datetime

PCAP = "c.pcapng"
KEY  = "R@ns0mwar3_V1ru5"
MD5  = hashlib.md5(KEY.encode()).hexdigest()

### Extract all data frames on backdoor ports
out = subprocess.check_output(
    ["tshark", "-r", PCAP, "-Y", "tcp.port==8899 or tcp.port==9999",
     "-T", "fields", "-e", "frame.number", "-e", "tcp.stream",
     "-e", "tcp.payload", "-e", "tcp.dstport", "-e", "frame.time"],
    text=True
)

### Group by (stream, direction) to handle TCP fragmentation
groups = defaultdict(list)
for line in out.strip().split("\n"):
    parts = line.split("\t")
    if len(parts) < 5 or not parts[2]:
        continue
    fnum, stream, hexdata, dstport, ts = parts
    direction = "c2s" if int(dstport) in (8899, 9999) else "s2c"
    groups[(int(stream), direction)].append((int(fnum), hexdata, ts))

def decrypt_one(hex_data, hour, minute):
    raw = bytes.fromhex(hex_data)
    text = raw.decode("utf-8")
    ts_hex = hex(int(datetime(2024, 1, 18, hour, minute, 0).timestamp()))[2:].zfill(8)
    xor_key = bytes.fromhex(ts_hex)
    xored = "".join(chr(ord(c) ^ xor_key[i % 4]) for i, c in enumerate(text))
    b64 = xored.strip()
    if len(b64) % 4:
        b64 += "=" * (4 - len(b64) % 4)
    return ARC4.new(MD5.encode()).decrypt(base64.b64decode(b64))

for (stream, direction), frames in sorted(groups.items()):
    frames.sort()
    i = 0
    while i < len(frames):
        fnum, hexdata, ts = frames[i]
        h, m = map(int, re.search(r"T(\d{2}):(\d{2})", ts).groups())

        # Concatenate consecutive fragments if needed (TCP segmentation)
        hex_to_try = hexdata
        j = i + 1
        plain = None
        while True:
            try:
                plain = decrypt_one(hex_to_try, h, m)
                break
            except (UnicodeDecodeError, Exception):
                if j < len(frames):
                    hex_to_try += frames[j][1]
                    j += 1
                else:
                    break

        if plain:
            tag = "→" if direction == "c2s" else "←"
            print(f"[stream {stream} {tag} {h:02d}:{m:02d}] {plain.decode().strip()}")
        i = j
```
