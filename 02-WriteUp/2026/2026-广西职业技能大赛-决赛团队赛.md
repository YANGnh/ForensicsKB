## 0. 检材概览与工具准备

### 检材信息
| 项目 | 内容 |
|------|------|
| 文件名 | `evidence.ad1` |
| 文件大小 | ~17 GB |
| 格式 | AccessData Logical Image (AD1) |
| 内容 | 一台 Ubuntu 服务器的磁盘逻辑镜像 |

### 第一步：识别镜像格式

拿到一个 17GB 的未知文件，先看文件头和类型：

```bash
$ file evidence.ad1
evidence.ad1: data          # file 命令不认识

$ xxd evidence.ad1 | head -1
00000000: 4144 5345 474d 454e 5445 4446 494c 4500  ADSEGMENTEDFILE.
```

看到 `ADSEGMENTEDFILE` 魔数，这是 AccessData 公司的 **AD1 格式**（FTK Imager 生成的逻辑镜像）。

> **知识点**：常见镜像格式有 E01(EWF)、AFF、RAW(dd)、AD1。每种格式有不同的魔数。AD1 是 AccessData 的专有格式，和 E01 不同。

### 第二步：找工具挂载 AD1

常见思路：
1. `ewf-tools`（`ewfmount`）→ **不支持 AD1 扩展名**
2. `xmount` → 输入格式列表里 **没有 AD1**
3. `afflib` → **不支持**

```bash
$ apt-cache search ad1    # Kali 仓库里没有
$ xmount --info           # 支持的格式：aff, aff3, aaff, aewf, raw, dd, vdi, qcow, ewf
```

> **关键教训**：AD1 在开源工具链中支持较差，需要专门方案。

通过网络搜索 `AD1 format parser open source`，找到几个候选：

| 工具 | 语言 | 特点 |
|------|------|------|
| [al3ks1s/AD1-tools](https://github.com/al3ks1s/AD1-tools) | Shell/C | 可挂载，功能最全 |
| [pcbje/pyad1](https://github.com/pcbje/pyad1) | Python | 纯 Python 解析 |
| [dissect.evidence](https://docs.dissect.tools) | Python | 支持 AD1v4，生态完善 |

**最终选择 `dissect`**（可通过 pip 安装，生态完善，支持 AD1v4）：

```bash
$ python3 -m venv forensic_env
$ source forensic_env/bin/activate
$ pip install dissect
```

### 第三步：读取 AD1 并了解镜像结构

```python
from dissect.evidence.ad1 import AD1

ad1 = AD1(open('evidence.ad1', 'rb'))
root = ad1.get('/')

# 查看根目录
for name in root.listdir():
    print(name)
# 输出：ubuntu-vg-ubuntu-lv [28900MB]:NONAME [ext4]
```

只有一个条目——这是一个 LVM 逻辑卷上的 ext4 文件系统。继续向下钻取：

```python
vol = ad1.entry(root.listdir()[0])
root_entry = ad1.entry(f"{vol.name}/[root]")

for name in root_entry.listdir():
    print(name)
# 输出：lost+found, boot, bin, etc, home, usr, var, ...
```

这是标准的 Ubuntu Linux 文件系统布局。**至此，我们有了完整的文件系统访问能力。**

> **建立路径映射**：
> ```
> / → <vol_name>/[root]/
> /etc → <vol_name>/[root]/etc/
> /home/dev → <vol_name>/[root]/home/dev/
> ```

后续所有题目都通过遍历这个文件系统来取证。

### Q1. 服务器操作系统版本号

**答案**：`flag{24.04}`

**思路**：操作系统的版本号在哪里？Linux 常识告诉你几个地方：

- `/etc/os-release` — systemd 系统标准
- `/usr/lib/os-release` — 备用路径
- `/etc/issue` — 登录提示
- `/etc/lsb-release` — Ubuntu 特有

```python
os_release = ad1.entry(f"{base}/usr/lib/os-release")
print(os_release.open().read().decode())
# PRETTY_NAME="Ubuntu 24.04.4 LTS"
# VERSION_ID="24.04"
```

取 `VERSION_ID` 的值 `24.04`。

> **补充**：`/etc/os-release` 通常是 `/usr/lib/os-release` 的软链接，AD1 镜像中可能只捕获了其中一个。

### Q2. 开发者使用服务器监控软件是什么

**答案**：`flag{xterminal}`

**思路**：监控软件会在哪留下痕迹？几个方向：

1. **用户家目录下的隐藏配置** — 很多监控/管理工具有 `~/.xxx` 配置目录
2. **systemd 服务** — 是否注册了监控服务
3. **进程列表/crontab** — 定时采集任务
4. **/opt 或 /usr/local** — 手动安装的软件

在 `/home/dev/` 下查找隐藏目录：

```python
home = ad1.entry(f"{base}/home/dev")
for name in home.listdir():
    if name.startswith('.'):
        print(name)
# 输出中看到：.xterminal
```

│           └── xl.meta   # ← 实际数据在这里

│           └── xl.meta

def extract_clean_text(data):

        if idx >= 0:
            return text[idx:]
    return text
