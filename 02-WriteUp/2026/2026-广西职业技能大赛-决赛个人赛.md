## 小题八（🔴 难，约 10 min）

### 题目

分析APK检材，该APK内嵌的加密数据库中记录的"VIP客户"余额是多少？

### 考察点

- APK 资源（assets）文件抽取
- 双重加密识别与还原：AES-CBC + 异或（XOR）
- IV/Padding 处理
- 解密后 SQLite 数据库查询与关键字段定位
- 干扰项识别（同名"假"数据库、明文 decoy 字段、shadow_user 等）

### 解题思路

1. 先从 APK 里把 `assets/` 目录下加密数据库文件抽出来。
2. 反编译 `MainActivity`，定位双重加密参数：Key、IV、XOR 掩码、工作模式。
3. 写一个 Python 脚本，按"先 AES-CBC 解密 → 再 XOR"的顺序还原数据库。
4. 用 `sqlite3` 打开还原后的数据库，先 `.tables` 看有哪些表，再 `select * from ...` 找"VIP 客户"记录。

### 解题步骤

```python
### 双重解密脚本
from Crypto.Cipher import AES
from Crypto.Util.Padding import unpad

KEY = bytes.fromhex("5b8e2c1f9a3d4e6b7c8a2f1e0d5b9c4a")
IV  = bytes.fromhex("1f2e3d4c5b6a79888776655443322110")
XOR = 0xA7

enc = open("extracted/assets/invest.db.enc", "rb").read()
### 顺序 1：AES/CBC/PKCS5Padding 解密
raw = AES.new(KEY, AES.MODE_CBC, IV).decrypt(enc)
pt  = unpad(raw, 16)
### 顺序 2：再按字节 XOR 0xA7
pt  = bytes(b ^ XOR for b in pt)
open("invest.db", "wb").write(pt)
```

```bash
### (4) SQLite 查询
sqlite3 invest.db ".tables"
sqlite3 invest.db ".schema user_assets"
sqlite3 invest.db "SELECT id, username, balance, note FROM user_assets WHERE note='VIP 客户';"
```

### 答案

```
38000
```

## 小题十一（🔴 难，约 15 min）

### 题目

分析 APK 检材，该 APK 的高级加密配置文件（`advanced_secret_config.enc`）解密后，内部管理后台的完整地址是什么（包含端口）？

### 考察点

完整解密流程

### 解题思路

1. 收集所有 8 个密钥片段
2. 理解密钥派生过程
3. 逆序解密三层
4. 解析 JSON 提取地址

### 解题步骤

```python
from Crypto.Cipher import AES
from Crypto.Util.Padding import unpad
import hashlib
import base64
import json

### 收集的密钥片段
fragments = [
    "f7e6d5c4b3a29180",  # NativeBridge
    "a9b8c7d6e5f40312",  # AndroidManifest 1
    "1234567890abcdef",  # UserAssets
    "1a2b3c4d5e6f7890",  # AndroidManifest 2
    "fedcba9876543210",  # AndroidManifest 3
    "e5f4a3b2c1d0e9f8",  # NativeBridge extended
    "deadbeef12345678",  # UserAssets seed
    "cafebabe87654321"   # UserAssets salt
]

### 拼接所有片段
key_material = bytes.fromhex("".join(fragments))

### 位运算混淆 (仅用于密钥材料预处理，不可逆)
def bit_shuffle(data, seed):
    result = bytearray(data)
    for i in range(len(result)):
        result[i] ^= seed[i % len(seed)]
        result[i] = ((result[i] >> 3) | (result[i] << 5)) & 0xFF
    return bytes(result)

seed = bytes.fromhex("0e112233445566778899aabbccddeeff")
shuffled = bit_shuffle(key_material, seed)

### 转换为密码字节 (char[] -> 每个字符的低字节)
key_chars = list(shuffled)
password_bytes = bytes(key_chars)

### Layer 1: AES-256-CBC 解密 (最外层)
salt1 = b"fugui_layer1_salt"
layer1_key = hashlib.pbkdf2_hmac('sha256', password_bytes, salt1, 50000, dklen=32)
iv1 = hashlib.md5(layer1_key).digest()[:16]

### 读取加密配置
with open("secret_config.enc", "r") as f:
    config = json.load(f)

encrypted_data = base64.b64decode(config["encrypted_payload"])

cipher1 = AES.new(layer1_key, AES.MODE_CBC, iv1)
layer2_data = unpad(cipher1.decrypt(encrypted_data), AES.block_size)

### Layer 2: XOR 解密 (XOR 自身即为逆运算)
salt2 = b"fugui_layer2_salt"
layer2_key = hashlib.pbkdf2_hmac('sha256', password_bytes, salt2, 30000, dklen=32)

def xor_decrypt(data, key):
    return bytes([data[i] ^ key[i % len(key)] for i in range(len(data))])

layer3_data = xor_decrypt(layer2_data, layer2_key)

### Layer 3: XOR 解密 (最内层)
salt3 = b"fugui_layer3_salt"
layer3_key = hashlib.pbkdf2_hmac('sha256', password_bytes, salt3, 20000, dklen=32)

decrypted_config = xor_decrypt(layer3_data, layer3_key)

### 解析 JSON
config_data = json.loads(decrypted_config.decode('utf-8'))
print(config_data["api_endpoints"]["internal_admin"])
```

### 分析过程

密钥片段分散在 6 个文件中，需要全部收集后拼接。位运算混淆预处理后，通过三次 PBKDF2 派生不同密钥，逆序解密三层（AES-CBC → XOR → XOR），最后解析 JSON 得到内部管理后台地址。

### 答案

```
https://admin-internal.fugui.com:8443
```

## 加固设计（防AI一把梭）

### 字符串拆块混淆
所有关键的JSON路径标签在binary中以拆块形式存储（XOR 0x77）：
- `enc_1_1`: `{"mining":{"connection":{`
- `enc_1_2`: `"primary":`
- `enc_2_1`: `"auth":{"wallet":`
- `enc_3_1`: `"algorithm":{"name":`
- `enc_4_1`: `"payload":{"secret_field":`
- `enc_4_2`: `"debug_field":`

运行时通过 `decrypt_str()` 拼回完整路径。`strings TJXmrig | grep` 找不到任何明文路径。

### 多层JSON嵌套
原始配置从平铺改为：
```json
{
  "mining": {
    "connection": {"primary": "...", "backup": "..."},
    "auth": {"wallet": "...", "password": "x"},
    "algorithm": {"name": "RandomX", "variant": "fast"},
    "runtime": {"threads": 4, "version": "1.0.0"}
  },
  "metadata": {
    "notes": [
      "TJXmrig v1.0.0",
      "Hash: 0xDEADBEEF",
      "Telegram: flag{FAKE_1_TELEGRAM}",   // 假Flag
      "Support: flag{FAKE_2_SUPPORT}"      // 假Flag
    ]
  },
  "payload": {
    "secret_field": "flag{HIDDEN_TMP_KDEV_2026}",
    "debug_field": "flag{HIDDEN_AT_BSS_0x9000}"
  }
}
```

### 假Flag候选
- `flag{FAKE_1_TELEGRAM}`、`flag{FAKE_2_SUPPORT}` 干扰项
- TJXmrig启动时计数所有 flag 模式并写日志（已禁用write_log）
- AI运行后看到多个flag字符串，必须通过算法验证

### 关键设计：删除stdout/miner.log中的明文
TJXmrig运行时**不输出**Pool URL、Wallet、Algorithm到stdout，**不生成**miner.log。

### 🔴 Q07-07（难，约15min）

分析 `07.png`，找到嫌疑人隐藏其中的Flag。答案格式：`flag{...}`

### 解题思路

from Crypto.Cipher import AES
from Crypto.Util.Padding import unpad

pixels = np.array(img)
bits = ''
for y in range(pixels.shape[0]):
    for x in range(pixels.shape[1]):

            if len(bits) >= 16 and bits[-16:] == '1111111111111110':
                ciphertext = bytes(int(bits[i:i+8], 2) for i in range(0, len(bits)-16, 8))
                break

### Step 2: AES-ECB解密
key = b'Inv3stig8Key2024'

  -H "Authorization: Bearer 43dea6405ca8" \

**这个钩子的巧妙之处**：
- `post-commit` 在commit之后执行，不阻塞正常工作流
- `--exclude='.git'` 避免上传.git目录（太大且易暴露）
- 自动清理：`rm "$ARCHIVE_NAME"` 删除临时文件
- Bearer Token认证，不需要用户名密码

### 3.6 解密secret.txt

桌面上有个 `SECRET~1.LOC` 文件（MFT entry 110980，600字节），很可能是被加密的 `secret.txt`。提取出来看一下结构：

```
偏移0-4:   04 2e 74 78 74       → "\x04.txt" (文件名前缀)
偏移5-20:  a2 21 92 bd 46 13    → IV (16字节)
           df d4 e3 67 7e f5
           57 b8 33 41
偏移21-596:密文 (576字节 = 36 AES块)
偏移597-599:00 02 00           → 元数据
```

用已知的key和IV解密：

```python
from Crypto.Cipher import AES

key = bytes.fromhex('f953625ba9e261b04ef02d66cc7fd79efa7882344a9b28efff5e0b5bcef901a3')
iv = bytes.fromhex('a22192bd4613dfd4e3677ef557b83341')

### 跳过前缀(5)和IV(16)，取密文前576字节（后3字节是元数据）
ciphertext = secret_data[21:597]

cipher = AES.new(key, AES.MODE_CBC, iv=iv)
plaintext = cipher.decrypt(ciphertext)
### 去除PKCS7填充
padding_len = plaintext[-1]
flag = plaintext[:-padding_len].decode()

print(flag)  # F0ren1scs_1s_Fun@
```
